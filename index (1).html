一、案例背景

本系統提供大學教務處、系辦公室及授課教師使用，集中管理學生基本資料、開設課程與學生選課紀錄。

要解決的問題

  • 快速查詢學生基本資料與所屬系所。
  • 查詢每位學生的選課紀錄及成績。
  • 統計每門課程的選課人數。
  • 減少人工整理試算表所花費的時間與錯誤。

教務行政人員

管理學生、課程與選課資料。

授課教師

查詢修課名單及學生成績。

系辦助理

統計各系學生與課程選修狀況。

學生

查詢個人選課與修課紀錄。

學習目標

練習 SELECT、WHERE、ORDER BY、JOIN、GROUP BY、COUNT 等 SQL 語法，並理解修改查詢條件後，結果筆數與內容為何改變。

五、修改 SQL 前後的結果比較

以下使用相同資料庫，逐步增加查詢條件，觀察資料筆數的變化。

版本 A：查詢所有學生

SELECT * FROM STUDENTS;
結果：5 筆資料

沒有 WHERE 條件，因此顯示所有學生。

版本 B：只查詢資工系學生

SELECT * FROM STUDENTS
WHERE department = '資工系';
結果：2 筆資料

加入 WHERE 條件，只保留系所為資工系的學生。

版本 C：只查詢二年級以上的資工系學生

SELECT * FROM STUDENTS
WHERE department = '資工系'
AND grade >= 2;
結果：1 筆資料（王小明）

增加 AND grade >= 2，必須同時符合兩項條件。

結果數量變化

5 筆A
2 筆B
1 筆C

修改 SQL 的原因與影響

  • 加入 WHERE：縮小資料查詢範圍。
  • 使用 AND：要求多個條件必須同時成立。
  • 修改比較運算子：改變符合條件的資料。
  • 加入 ORDER BY：不改變筆數，但會改變顯示順序。
  • 使用 GROUP BY：依欄位分組並統計。
