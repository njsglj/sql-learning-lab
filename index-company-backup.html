01 / BUSINESS CASE

案例背景｜COMPANY 公司管理系統

用一個虛構企業，理解資料庫為什麼需要關聯。

公司遇到什麼問題？

假設 COMPANY 是一間同時進行產品開發與內部改善專案的公司。公司有研發、行政與總部三個部門，員工可能參與不同部門負責的專案。管理者需要快速確認員工隸屬、主管關係、專案成員與投入時數。

如果把員工、部門、專案和工時全部塞進同一張表，員工資料會因參與多個專案而重複，更新時也容易出現不一致。因此我們把資料拆成六張表，再透過主鍵與外來鍵建立關聯。

04 / RESULT COMPARISON

結果比較｜一個條件，答案就不同

比較相同資料庫中，不同 SQL 寫法造成的結果差異。

VERSION A / 未加條件

列出所有員工

查詢整張 EMPLOYEE 表，會取得所有 8 位員工。

SELECT Fname, Salary FROM EMPLOYEE;

8筆結果
→
VERSION B / 加入篩選

只看高薪員工

加入 WHERE Salary > 40000，只留下薪資高於 40,000 的員工。

SELECT Fname, Salary FROM EMPLOYEE WHERE Salary > 40000;

2筆結果

為什麼結果會改變？

SQL 的 WHERE 是篩選條件。沒有 WHERE 時，資料表符合查詢欄位的每一列都會出現；加上條件後，只有判斷結果為 TRUE 的列會保留。這個案例的薪資門檻為 40,000，因此筆數從 8 筆減少為 2 筆。

LEARNING NOTES

練習時，記得這三件事

① 先讀懂題目要回答的業務問題，再決定要查哪張表。② JOIN 的欄位要對應主鍵與外來鍵，不要只靠姓名配對。③ NULL 代表未知或未記錄，不等於 0；COUNT(欄位) 也不會計算 NULL。
