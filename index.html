01 / CASE BACKGROUND

案例背景｜校園選課管理系統

教學用虛構資料

為什麼需要這套資料庫？

學校每學期都要處理學生、課程與選課紀錄。若資料散落在不同試算表，容易發生重複登錄、名單不一致，也難以快速統計修課人數。本系統將資料分表管理，透過主鍵與外鍵建立關聯，讓教務人員與教師能快速取得資訊。

04 / RESULT COMPARISON

結果比較｜同一問題，不同 SQL 寫法

問題：查詢每門課的修課人數。比較 LEFT JOIN 與 INNER JOIN 的差異。

寫法 A｜列出所有課程

SELECT c.course_name, COUNT(e.student_id) AS total FROM COURSES c LEFT JOIN ENROLLMENTS e ON c.course_id=e.course_id GROUP BY c.course_id, c.course_name;

結果：所有課程都會出現，無人選課時人數顯示 0。LEFT JOIN 保留左表 COURSES 的全部資料。

寫法 B｜只列出有人選的課程

SELECT c.course_name, COUNT(e.student_id) AS total FROM COURSES c INNER JOIN ENROLLMENTS e ON c.course_id=e.course_id GROUP BY c.course_id, c.course_name;

結果：沒有選課紀錄的課程不會出現。INNER JOIN 只保留兩表成功配對的資料。

差異整理

比較項目LEFT JOININNER JOIN
沒有學生選課的課程保留，COUNT 顯示 0不顯示
資料保留原則保留左表全部課程只保留成功配對資料
適用情境完整課程開課統計只分析實際有人修課的課程

小提醒：LEFT JOIN 時使用 COUNT(e.student_id)，不要用 COUNT(*)，因為 COUNT(*) 仍會計入被保留的左表資料列。
